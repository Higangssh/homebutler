# Report, doctor and inventory

`report`, `doctor`, `inventory_scan`, `inventory_export` and `config_validate` answer what changed and what is wrong. `report` is classed `write` because it saves a snapshot.

<Tool>

### report

<Badge tone="warning">write</Badge>

Compares the machine with the last saved snapshot and returns what changed, what needs attention, and what to do next. By default it also saves a new snapshot, which moves the point every later comparison starts from, so a loop that calls `report` leaves nothing to compare against. In [read-only mode](/agents/read-only-mode) the tool is offered and always runs with `no_save`.

#### Arguments

| Argument | Type | Description |
| --- | --- | --- |
| `keep` | integer | Number of snapshots to keep on disk. Older ones are deleted when a new one is saved. Default: `30`. |
| `no_save` | boolean | `true` compares without writing a snapshot. With no earlier snapshot it returns a `skipped` change and creates no baseline. A server started with `--max-risk read` sets this to `true` whatever you send. Default: `false`. |
| `server` | string | Server from your config to run on. See [Run a tool on another server](/mcp#run-a-tool-on-another-server). |

#### Response

| Field | Type | Meaning |
| --- | --- | --- |
| `schema_version` | integer | Version of the document shape. Always `1`. |
| `timestamp` | string | When the report ran, in RFC 3339 format (UTC). |
| `server_name` | string | Name of the server in your config, or the host name when the config has none. |
| `is_baseline` | boolean | `true` when there was no earlier snapshot to compare with. A baseline has no real changes. |
| `snapshot_saved` | boolean | `true` when this run wrote a new snapshot. `false` with `no_save`, and always `false` when the server runs with [`--max-risk read`](/agents/read-only-mode). |
| `system` | object or null, optional | The same fields as [`system_status`](/mcp/system#system_status), without `schema_version`. Left out when the system could not be read. |
| `running_count` | integer or null | Number of running containers. `null` when Docker did not answer. |
| `stopped_count` | integer or null | Number of stopped containers. `null` when Docker did not answer. |
| `public_port_count` | integer or null | Number of ports listening on every interface. `null` when the port collector did not answer. |
| `status` | array of strings | The same facts as `system`, `running_count` and `public_port_count`, written as sentences for a person. |
| `needs_attention` | array of objects | Things that are wrong now or became wrong since the last snapshot. |
| `needs_attention.kind` | string | What the item is about: `memory`, `disk`, `container` or `port`. |
| `needs_attention.text` | string | The sentence a person reads. |
| `needs_attention.target` | string, optional | The mount, container or port the item is about. Left out when the item is about several. |
| `notable_changes` | array of objects | What moved since the last snapshot, one entry per change. |
| `notable_changes.kind` | string | One of `gone`, `new`, `replaced`, `image`, `state`, `port`, `disk` or `skipped`. See [Report](/changes/report). |
| `notable_changes.target` | string | What the change happened to: a container, a port such as `:8101/tcp`, a process or a mount. For `skipped`, empty when there is no snapshot to compare with and `containers` when Docker did not answer. |
| `notable_changes.detail` | string, optional | What happened, such as `recreated, a823d9a5eec8 → 75c7b65b7c79`. Left out when the kind says it all. |
| `notable_changes.text` | string | The line the CLI prints. |
| `compared_to` | string, optional | Timestamp of the snapshot this run was compared with. Left out for a baseline. |
| `suggested_actions` | array of objects | What to do about the findings. |
| `suggested_actions.text` | string | The suggestion as a sentence. |
| `suggested_actions.command` | string, optional | The command that carries it out. Left out when the suggestion has none. |
| `suggested_actions.runner` | string, optional | Who can run `command`: `mcp` (call `tool`), `cli` (the operator runs it in a terminal) or `shell` (not a homebutler command). Left out when there is no `command`. |
| `suggested_actions.tool` | string, optional | The MCP tool that does what `command` does. Present only when `runner` is `mcp`. |
| `failed_collectors` | array of strings, optional | Collectors that did not answer: `docker`, `ports` or `processes`. A count is trustworthy only when its collector is not listed here. Left out when all answered. |
| `warnings` | array of strings, optional | Messages about collectors that had trouble. Left out when there are none. |

### doctor

<Badge tone="success">read</Badge>

Runs a read-only diagnosis of resource pressure, stopped containers, ports open on every interface, backup age and drills, notification readiness, watch setup, config file permissions, and configured Proxmox endpoints. Each finding names the command that addresses it, and `runner` says whether a tool, the CLI or a shell runs it.

#### Arguments

| Argument | Type | Description |
| --- | --- | --- |
| `backup_max_age_hours` | integer | A backup older than this many hours produces a warning. Default: `168`. |
| `server` | string | Server from your config to run on. See [Run a tool on another server](/mcp#run-a-tool-on-another-server). |

#### Response

| Field | Type | Meaning |
| --- | --- | --- |
| `schema_version` | integer | Version of the document shape. Always `1`. |
| `timestamp` | string | When doctor ran, in RFC 3339 format (UTC). |
| `server_name` | string | Name of the server in your config, or the host name. |
| `status` | string | The worst severity among the findings: `pass`, `warn` or `fail`. |
| `summary` | object | Findings counted by severity. |
| `summary.pass` | integer | Number of `pass` findings. |
| `summary.warn` | integer | Number of `warn` findings. |
| `summary.fail` | integer | Number of `fail` findings. |
| `findings` | array of objects | One entry per finding. A run with no problems returns one `pass` finding in the `overall` category. |
| `findings.severity` | string | `pass`, `warn` or `fail`. |
| `findings.category` | string | One of `backup`, `config`, `docker`, `exposure`, `incomplete`, `notifications`, `overall`, `proxmox`, `report`, `system` or `watch`. |
| `findings.title` | string | Short name of the finding. |
| `findings.detail` | string, optional | What doctor found. Left out when the title says it. |
| `findings.action` | string, optional | What to do about it. Left out when nothing is needed. |
| `findings.command` | string, optional | The command that carries the action out. Left out when there is none. |
| `findings.runner` | string, optional | Who can run `command`: `mcp`, `cli` or `shell`. Present whenever `command` is. |
| `findings.tool` | string, optional | The MCP tool that does what `command` does. Present only when `runner` is `mcp`. |

### inventory_scan

<Badge tone="success">read</Badge>

Collects the server's system status, every container, and every listening port into one document. Ports that a container publishes carry the container's name and image.

#### Arguments

| Argument | Type | Description |
| --- | --- | --- |
| `server` | string | Server from your config to run on. See [Run a tool on another server](/mcp#run-a-tool-on-another-server). |

#### Response

| Field | Type | Meaning |
| --- | --- | --- |
| `server_name` | string | Name of the server in your config, or the host name. |
| `host` | string | Address of the server from your config, or the host name of the machine when the config has no server entry for it. |
| `system` | object or null | The same fields as [`system_status`](/mcp/system#system_status), without `schema_version`. `null` when the system could not be read. |
| `containers` | array of objects | Every container, running or not. |
| `containers.id` | string | Short container ID. |
| `containers.name` | string | Container name. |
| `containers.image` | string | Image the container runs. |
| `containers.status` | string | Status text from Docker, such as `Running · 41s`. |
| `containers.state` | string | Docker state, such as `running` or `exited`. |
| `containers.ports` | string | Published ports as Docker prints them. Empty when none are published. |
| `ports` | array of objects | Every listening port. Same shape as [`open_ports`](/mcp/system#open_ports). |
| `ports.protocol` | string | Transport protocol. `tcp`. |
| `ports.address` | string | Address the socket is bound to. |
| `ports.port` | string | Port number, as a string. |
| `ports.container` | string, optional | Container that publishes the port, as `name (image)`. Left out when no container does. |
| `ports.pid` | string, optional | Process ID. Left out when the process is not readable. |
| `ports.process` | string, optional | Process name. Left out when the process is not readable. |
| `failed_collectors` | array of strings, optional | Collectors that did not answer: `docker` or `ports`. Left out when all answered. |
| `warnings` | array of strings, optional | Messages about collectors that had trouble. Left out when there are none. |

### inventory_export

<Badge tone="success">read</Badge>

Exports the inventory as a Mermaid diagram or as JSON. `mermaid` works only on the local machine. With `server` set, only `json` is supported, and `mermaid` returns an error. With `format` set to `json` the response is the same document as [`inventory_scan`](#inventory_scan).

#### Arguments

| Argument | Type | Description |
| --- | --- | --- |
| `format` | string | Export format: `mermaid` or `json`. Any other value returns `unsupported format: "<value>" (supported: mermaid, json)`. Default: `mermaid`. |
| `server` | string | Server from your config to run on. See [Run a tool on another server](/mcp#run-a-tool-on-another-server). |

#### Response

| Field | Type | Meaning |
| --- | --- | --- |
| `format` | string | The format that was produced, `mermaid`. |
| `content` | string | The Mermaid source for a diagram: the home network, the server, its containers, and the ports that containers publish. |

<Accordion title="Examples">

The two fields apply to `format` set to `mermaid`.

The response, shortened to the example containers by removing whole lines from `content`:

Arguments:

```json
{
  "format": "mermaid"
}
```

Response:

```json
{
  "format": "mermaid",
  "content": "graph TD\n  home[\"🏠 Home Network\"] --> homelab[\"🖥 homelab<br/>127.0.0.1\"]\n  homelab --> c0[\"📦 web<br/>running\"]\n  homelab --> c2[\"📦 uptime-kuma<br/>running\"]\n  homelab --> p8[\"🌍 :8102/tcp<br/>web\"]\n  c0 -. exposes .-> p8\n  homelab --> p9[\"🌍 :8101/tcp<br/>uptime-kuma\"]\n  c2 -. exposes .-> p9\n"
}
```

### config_validate

<Badge tone="success">read</Badge>

Checks the config file that this MCP server runs on and reports which file was read, which rule selected it, what was read from each section, and anything wrong or silently ignored, such as a misspelled key. The tool takes no `server` argument: it answers about this machine's file.

#### Arguments

| Argument | Type | Description |
| --- | --- | --- |
| `strict` | boolean | `true` counts warnings as failures in `passed`. Default: `false`. |

#### Response

| Field | Type | Meaning |
| --- | --- | --- |
| `passed` | boolean | `true` when the file has no errors. With `strict`, warnings count as failures too. |
| `errors` | integer | Number of findings with severity `error`. |
| `warnings` | integer | Number of findings with severity `warning`. |
| `result` | object or null | What was checked. |
| `result.path` | string | The config path that was checked. |
| `result.source` | string | Which rule selected the path: `flag` (`--config`), `env` (`$HOMEBUTLER_CONFIG`), `xdg` (`~/.config/homebutler/config.yaml`), `cwd` (`./homebutler.yaml`) or `none` (no file, built-in defaults). |
| `result.exists` | boolean | `true` when the file exists. |
| `result.sections` | array of objects, optional | What was read from each section of the config. Left out when no file exists. |
| `result.sections.name` | string | Section name, such as `servers`, `alerts` or `notify`. |
| `result.sections.present` | boolean | `true` when the section is in the file. |
| `result.sections.summary` | string | What homebutler read from the section, or `not set`. |
| `result.findings` | array of objects, optional | Problems and silently ignored keys. Left out when there are none. |
| `result.findings.severity` | string | `error` (something will not work) or `warning` (the file parses but probably does not do what you meant). |
| `result.findings.field` | string, optional | The config field, such as `servers[1].host`. Left out when the finding is about the whole file. |
| `result.findings.message` | string | What is wrong. |
| `result.findings.hint` | string, optional | How to fix it. Left out when there is no hint. |
| `result.valid` | boolean | `true` when there are no errors. |

<Accordion title="Examples">
